# Methodology Document

## 1. Problem Framing
The task requires maximizing **F0.5**, a metric that weights precision higher than recall. Thus, falsely linking two distinct entities is penalized more heavily than failing to link true duplicates. We framed the problem as a high-recall **Blocking** stage followed by a precision-focused **Binary Pair Classification** stage.

## 2. Preprocessing
We implemented robust standardizers:
- **Names**: Lowercased, stripped punctuation, collapsed whitespace.
- **Addresses**: Lowercased, stripped punctuation, and expanded standard abbreviations (`st -> street`, `blvd -> boulevard`).

## 3. Candidate Generation (Blocking)
To avoid testing every $N \times M$ pair, we generated candidate pairs using two strategies:
1. **Exact Match**: Joins on exactly matching normalized name + normalized address.
2. **Token Match**: Joins on the first token of the normalized business name. 

These strategies were unioned and deduplicated. True pairs missed by these rules can never be recovered, so this step acts as our *recall ceiling*.

## 4. Feature Engineering
For each candidate pair, we computed pairwise interactions directly:
- **Name Features**: Levenshtein edit similarity (`difflib.SequenceMatcher`) and Token Jaccard index.
- **Address Features**: Levenshtein edit similarity and Token Jaccard index.
- **Country Features**: Binary flag for identical countries.

## 5. Model Selection and Training
We selected a **RandomForestClassifier** with `class_weight='balanced'`. 
- **Positives**: Candidate pairs present in `train_ground_truth.tsv`.
- **Negatives**: Candidate pairs generated by our blockers that are *not* in the ground truth. This acts as implicitly mined **hard negatives**, forcing the model to learn fine decision boundaries rather than distinguishing between trivial random pairs.

## 6. Threshold Tuning & Validation
We split the `train_source1.tsv` entities into an 80/20 train/validation split *before* candidate generation to prevent data leakage. The `predict_proba` outputs on the validation set were evaluated at 81 different thresholds (0.1 to 0.9). We selected the exact threshold that maximized the empirical F0.5 score on the validation split. 

## 7. Post-Processing & Output
- **Duplicate handling**: When a candidate was predicted multiple times by different routes, we aggregated and took the maximum probability.
- **Singletons**: Source 1 entities with no candidates scoring above the tuned threshold are explicitly recorded with an empty string, rightfully earning credit for correctly identifying "no-match" scenarios.
